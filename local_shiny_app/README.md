# RentLens (`rentalapp`)

A Shiny app for renters: budget check, listing check, options within budget, map
(with key places, MRT/LRT stations and map selections applied to every page), price
trends, area comparison (districts, Area A vs B), property comparison, value for
money, shortlist and raw transactions. It is structured as
an R package, following
[Engineering Production-Grade Shiny Apps](https://engineering-shiny.org/structuring-project.html).

## Run it

```r
# one-time
install.packages(c("shiny", "bslib", "DT", "dplyr", "plotly", "sass",
                   "leaflet", "leaflet.extras", "sf", "httr2", "pkgload", "testthat", "roxygen2"))

shiny::runApp("local_shiny_app")      # from the repo root, or "Run App" on app.R
```

## Layout

```
local_shiny_app/
├── app.R                  entry point: loads the package and calls run_app()
├── DESCRIPTION            package name, dependencies
├── NAMESPACE              generated by roxygen2: do not edit by hand
├── R/
│   ├── run_app.R          run_app(): the only exported function
│   ├── app_ui.R           page layout: sidebar + one tab per module
│   ├── app_server.R       wires the modules together
│   ├── app_config.R       app_sys() (paths into inst/), theme
│   ├── mod_*.R            one module per tab (UI + server), plus mod_filters (sidebar)
│   ├── fct_*.R            business logic: data, rent summaries, distances, map pieces
│   ├── utils_*.R          small helpers: formatting, bookmarking
│   └── rentalapp-package.R  package-wide imports
├── inst/extdata/          rentals.rds, mrt_stations.csv
├── data-raw/             scripts that rebuild inst/extdata/ from the source data
├── dev/                   developer scripts (run_dev.R, check.R)
├── tests/testthat/        unit tests for fct_/utils_ and module tests (testServer)
└── man/                   generated documentation
```

### How the pieces talk to each other

- `mod_filters_server()` owns the sidebar and returns reactives (`market`,
  `selection`, `comparables`, `budget`, ...). Every other module receives
  that list as `filters`.
- The shortlist is a `reactiveVal` created in `app_server()` and passed to the
  modules that add to it (Within budget, Map) and show it (Shortlist,
  Compare properties).
- The map selection (`new_map_selection()`) and saved areas
  (`new_saved_areas()`) are `reactiveValues` created in `app_server()`. The
  map writes them; `mod_filters_server()` applies the selection to `market`
  (the map itself uses `base`, before the selection), and Area A vs B reads
  the saved areas.
- Rental data is read once per R session by `rentals_data()` (`fct_data.R`),
  which also attaches each contract's nearest MRT/LRT station.

### Naming conventions

| Prefix   | Contains                                | Example                    |
|----------|-----------------------------------------|----------------------------|
| `mod_`   | a Shiny module: `mod_x_ui()` + `mod_x_server()` | `mod_map.R`       |
| `fct_`   | app logic with no Shiny inputs/outputs  | `budget_verdict()`         |
| `utils_` | generic helpers                         | `money()`                  |

## Development workflow

```r
# from local_shiny_app/
source("dev/run_dev.R")        # reload code and launch
source("dev/check.R")          # regenerate NAMESPACE + run tests
```

- Added a new `@importFrom` / `@export` tag? Run `roxygen2::roxygenise()`.
- Adding a tab: create `R/mod_newtab.R` with `mod_newtab_ui(id)` /
  `mod_newtab_server(id, filters)`, then add one line to `app_ui.R` and one to
  `app_server.R`.
- Data changed? Rebuild `sg_rental_map/data/rentals.rds`, then
  `source("data-raw/rentals.R")`.
- "Check a listing" looks up addresses with the OneMap Search API (no key
  needed); answers are cached for the R session.
- MRT/LRT stations: `inst/extdata/mrt_stations.csv` (columns `station, lat, lng,
  kind`), rebuilt from LTA's station-exit data with `source("data-raw/mrt_stations.R")`.
- Key places (universities, polytechnics, business districts, transport,
  hospitals) are listed in `destination_groups` in `R/fct_location.R`.
- Schools: `inst/extdata/schools.csv` (columns `name, level, postal, lat, lng`),
  rebuilt from MOE's school list (data.gov.sg), geocoded with OneMap, by
  `source("data-raw/schools.R")`.

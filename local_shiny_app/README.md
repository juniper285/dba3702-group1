# RentLens (`rentalapp`)

A Shiny app for renters: budget check, listing check, options within budget, map
(with key places, MRT/LRT stations and map selections applied to every page), price
trends, area comparison (districts, Area A vs B), property comparison, value for
money, shortlist and raw transactions. It is structured as
an R package, following
[Engineering Production-Grade Shiny Apps](https://engineering-shiny.org/structuring-project.html).

## Run it

```r
# one-time
install.packages(c("shiny", "bslib", "DT", "dplyr", "plotly", "sass",
                   "leaflet", "leaflet.extras", "sf", "httr2", "pkgload", "testthat", "roxygen2"))

shiny::runApp("local_shiny_app")      # from the repo root, or "Run App" on app.R
```

### How the pieces talk to each other

- `mod_filters_server()` owns the sidebar and returns reactives (`market`,
  `selection`, `comparables`, `budget`, ...). Every other module receives
  that list as `filters`.
- The shortlist is a `reactiveVal` created in `app_server()` and passed to the
  modules that add to it (Within budget, Map) and show it (Shortlist,
  Compare properties).
- The map selection (`new_map_selection()`) and saved areas
  (`new_saved_areas()`) are `reactiveValues` created in `app_server()`. The
  map writes them; `mod_filters_server()` applies the selection to `market`
  (the map itself uses `base`, before the selection), and Area A vs B reads
  the saved areas.
- Rental data is read once per R session by `rentals_data()` (`fct_data.R`),
  which also attaches each contract's nearest MRT/LRT station.

| Prefix   | Contains                                | Example                    |

## Data sources

Every data set the app uses, where it comes from and the code that pulls it.
Rebuild scripts live in `data-raw/` and write to `inst/extdata/`; run them
from the package root (`local_shiny_app/`).

| Data | Source | Pulled by | Shipped as |
|------|--------|-----------|------------|
| Rental contracts | [URA Data Service API](https://eservice.ura.gov.sg/maps/api/#introduction): private residential rental contracts | team's cleaning and geocoding (see below), then `data-raw/rentals.R` | `inst/extdata/rentals.rds` |
| MRT/LRT stations | [LTA MRT Station Exit (GeoJSON)](https://data.gov.sg/datasets/d_b39d3a0871985372d7e1637193335da5/view), data.gov.sg | `data-raw/mrt_stations.R` | `inst/extdata/mrt_stations.csv` |
| Schools | [MOE General information of schools](https://data.gov.sg/datasets/d_688b934f82c1059ed0a6993d2a829089/view), data.gov.sg, geocoded with the [OneMap Search API](https://www.onemap.gov.sg/apidocs/) | `data-raw/schools.R` | `inst/extdata/schools.csv` |
| Key places (universities, business districts, ...) | typed in by hand | `destination_groups` in `R/fct_location.R` | code |

None of these sources needs an API key, except the URA API.

### Rental contracts (URA)

URA publishes private residential rental contracts through its
[Data Service API](https://eservice.ura.gov.sg/maps/api/#introduction).
The API needs a free access key (register with URA) and a token generated
daily from that key; see URA's documentation for the endpoint and
parameters.

The team combined the URA downloads into `URA_Union_Cleaned.xlsx`, then added
each project's address and coordinates (`Address`, `Latitude`, `Longitude`)
and a `Match_Status` geocode-quality flag, giving
`URA_Union_Cleaned_with_Address.xlsx`. The scripts for those steps are not in
this repo. The Excel file is git-ignored (about 30 MB).

From there:

1. `sg_rental_map/app.R` converts the Excel file to `sg_rental_map/data/rentals.rds`
   on first run (see the root README).
2. `source("data-raw/rentals.R")` renames the columns and writes
   `inst/extdata/rentals.rds`:

```r
raw <- readRDS("../sg_rental_map/data/rentals.rds")
rentals <- data.frame(project = raw$project, ..., lat = raw$lat, lng = raw$lng,
                      geo_match = raw$match)
saveRDS(rentals, "inst/extdata/rentals.rds", compress = "xz")
```

### MRT/LRT stations (LTA, data.gov.sg)

data.gov.sg's poll-download endpoint returns a short-lived link to the
GeoJSON of every station exit. A station's location is the average of its
exits (188 stations, 41 of them LRT):

```r
dataset <- "d_b39d3a0871985372d7e1637193335da5"
poll <- jsonlite::fromJSON(paste0(
  "https://api-open.data.gov.sg/v1/public/api/datasets/", dataset, "/poll-download"))
exits <- jsonlite::fromJSON(poll$data$url)$features   # one row per station exit
stations <- aggregate(cbind(lat, lng) ~ name, data = exits, FUN = mean)
```

### Schools (MOE, data.gov.sg + OneMap)

MOE's school list has names, levels and postal codes but no coordinates, so
each postal code is looked up with OneMap, keeping only exact postal matches
(all 337 schools matched in October 2026). Only name, level, postal code and
location are kept; contact and staff details are dropped.

```r
dataset <- "d_688b934f82c1059ed0a6993d2a829089"
moe <- jsonlite::fromJSON(paste0(
  "https://data.gov.sg/api/action/datastore_search?resource_id=", dataset, "&limit=1000"
))$result$records

httr2::request("https://www.onemap.gov.sg/api/common/elastic/search") |>
  httr2::req_url_query(searchVal = postal, returnGeom = "Y", getAddrDetails = "Y", pageNum = 1) |>
  httr2::req_perform() |>
  httr2::resp_body_json()      # results[[i]]$LATITUDE / $LONGITUDE where $POSTAL matches
```

### Refreshing everything

```r
# from local_shiny_app/
source("data-raw/rentals.R")       # after sg_rental_map/data/rentals.rds is rebuilt
source("data-raw/mrt_stations.R")  # LTA station exits
source("data-raw/schools.R")       # MOE schools + OneMap (about a minute)
```

## Development workflow

```r
# from local_shiny_app/
source("dev/run_dev.R")        # reload code and launch
source("dev/check.R")          # regenerate NAMESPACE + run tests
```

- Added a new `@importFrom` / `@export` tag? Run `roxygen2::roxygenise()`.
- Adding a tab: create `R/mod_newtab.R` with `mod_newtab_ui(id)` /
  `mod_newtab_server(id, filters)`, then add one line to `app_ui.R` and one to
  `app_server.R`.
- Data changed? Rebuild `sg_rental_map/data/rentals.rds`, then
  `source("data-raw/rentals.R")`.
- "Check a listing" looks up addresses with the OneMap Search API (no key
  needed); answers are cached for the R session.
- Key places (universities, polytechnics, business districts, transport,
  hospitals) are listed in `destination_groups` in `R/fct_location.R`.
